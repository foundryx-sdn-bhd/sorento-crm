Columns (owner, 17 Oct)
On hand, SO, PO, Incoming PL, SPO, Forecast. No status or health level anywhere; negative numbers print red, nothing more.
Forecast: AutoCount's formula, confirmed
On hand - SO + PO + SPO. The 459 was SPO (BRW-BB 50, BRW-IR 385, BRW-IB 24). SRTWB1515: 495 - 10,390 + 2,438 + 459 = -6,998; AutoCount shows -6,994 because its on hand read 499 at the screenshot moment (the CRM copy has 495). BRW-BB: 0 - 7,312 + 1,734 + 50 = -5,528, equal to AutoCount.
SO counts like AutoCount (owner, Q3 b)
Ordered less delivered over open lines, covered lines included, Transferable = F orders left out. Counting them, the CRM reads 10,583; leaving out the 193 on 27 lines of 5 F orders at BRW-BB gives 10,390, AutoCount's figure to the unit. The fulfilment board counts F orders and drops covered lines, so its own figures can differ from this panel.
Incoming PL (Q2 a), never counted twice
Per item, the packing-list qty still to land that is on no SPO (by link or by container number). SRTWB1515: 686 on 5 packing lists, of which 459 is already on SPOs (and in the SPO column), so 227. Forecast incl. incoming PL = -6,771.
SO due by
Cuts SO only, by delivery date; supply is never cut. A line with no date or AutoCount's placeholder 1 Jan 2030 ("3001") is "No date" and counts in every view: 4,411 of SRTWB1515's 10,390.
Inactive locations (Q6, open)
Not counted, footnoted under the table (CON 32, JB SHOWR 1, PJ-SR 1, REJ100% 1). Crew to read AutoCount's rows for these locations to settle whether any of them is in AutoCount's 499.
Sample Request has no screen in the CRM yet; it gets the screen-4 chip when it is built. Read-only throughout: nothing is written to AutoCount.
