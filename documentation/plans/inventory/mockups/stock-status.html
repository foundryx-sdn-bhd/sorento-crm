Forecast (Q1, pending reconciliation; dropped if it is not AutoCount's formula)
Forecast = On hand - SO + PO + SPO, per location and in total. For SRTWB1515: 499 - 10,390 + 2,438 + 459 = -6,994, AutoCount's figure, if the SPO column totals 459 (the 459 the three other columns leave unexplained). The masked rows confirm or correct this before build.
  • BRW-BB: 0 - 7,312 + 1,734 + 50 = -5,528
  • MWH-IB: 120 - 1,860 + 504 + 0 = -1,236
  • BRW: 245 - 640 + 200 + 409 = 214
Incoming PL (Q2 a)
A column, filled on the Total row only (location rows show a dot): the part of open packing lists not yet on an SPO (1,800), then Forecast incl. incoming PL = -5,194. Not split by location: the CRM knows a PL's location only once it is an SPO.
SO due by (horizon)
Cuts SO only, by line delivery date (else the order's). Supply is never cut. "Nov" drops SO-2610-0501 (10 Dec, 800): SO 9,590, forecast -6,194.
No status column (owner, 17 Oct)
No High / Backorder / Healthy label anywhere. The columns that matter: On hand, SO, PO, Incoming PL, SPO. Negative numbers print in red, nothing more. Item chips state on hand and SO, not a judgement.
SO counts like AutoCount (owner, Q3 b)
Every open SO line counts, including a line CS marked "covered" in the CRM (SO-2610-0455 in the BRW-BB documents, tagged "covered in CRM", still in the -7,312). The fulfilment board leaves covered lines out, so its SO can read lower than this panel: the panel follows AutoCount.
Documents
A location expands to its SO / PO / SPO, sorted by due date; each number opens the document in a new tab. A/O columns are not shown (the CRM has no A/O figure).
Sample Request has no screen in the CRM yet; it gets the screen-4 chip when it is built. Read-only throughout: nothing is written to AutoCount.
