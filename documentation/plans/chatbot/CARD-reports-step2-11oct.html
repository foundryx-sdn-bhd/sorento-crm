What changes for a customer

Report questions (top sellers, sales totals, outstanding, sales by month or channel) go through one tool. The bot remembers the last report in Focus, the memory it already has. A follow-up like "only dealer", "by month instead", "top 5" or "amount instead" changes the last report. It no longer starts over or gets misread as a customer or product. Every value carried from earlier is shown in the reply header, e.g. Period: Oct 2026 (from earlier). Grants, dealer limits, scope and the look of the reply stay exactly as today.

Proposal

  1. One read tool crm_report, built by extending the existing sales-ranking engine. The report-engine plan (section 7) already plans this fold. Grants, dealer limits, scope and the reply formats stay the services' own.
  2. Low stock stays its own tool. It creates a reorder run and a file, so it is an action: reads generic, actions specific. The sales-analysis Excel stays too.
  3. Old tools stay available until crm_report passes the gate for that kind of report.
  4. One report entry in Focus. No new memory system: today's ranking entry (Focus.sales_ranking_frame) is extended to every report kind and absorbs the top-selling and outstanding carries. A follow-up changes that entry; a different report or subject starts a fresh one.
  5. Carried values shown in the header. Defaults only where CLARIFY-POLICY allows; rankings still ask for period, metric and top N (owner rule).
  6. Static prompt: one report section replaces the report rules, the same text every turn (lesson of the prompt-diet test: per-message parts break the cache).

Two ways for the parser to describe a report (decided by test)

F, meaning output: the parser writes what was asked (new or refine, measure, group by, filters as the user's words, period, top, sort). Code turns it into the tool call.
T, tool call: the parser writes the tool's own parameters (still the user's words where ids go; the resolver fills ids, the model never invents them).
Both use the same static prompt. We compare pass, tokens, cache share and p95. A tie goes to F, because it keeps the tool's details out of the prompt.
