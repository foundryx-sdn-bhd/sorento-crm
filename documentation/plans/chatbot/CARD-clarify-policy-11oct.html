Clarify policy: when the chatbot should ask, and when it should just answer

Lane CLARIFY-POLICY, 11 Oct 2026. For owner rulings on Q1 to Q5 at the bottom. Customer names masked.

Why

5 of 47 hidden eval failures are the bot asking when it should have answered, plus loops (same question 3 times). Today each topic decides on its own when to ask, in 29 places, and nothing stops the bot repeating its own question.

Proposed rules (every topic)

1. Default and say so. If a missing detail has a safe default, answer with it and say the assumption in one line, with how to change it. Example: "Latest delivery for SRT391-GM: DO 202610-0668, 5 Oct. Another month? Reply with the month." Ask only when there is no safe default, or a wrong guess is costly (money, a stock promise, the wrong file to a dealer).
2. Skip pointless menus. If every choice leads to the same answer (all "no promotion", only one choice has data), answer directly.
3. Loop breaker. Never ask the same question a third time. Instead: best answer from what we know, plus an offer to hand over.
4. Never stuck. Every turn ends in an answer, a different question, or a handover offer.
5. No word lists. The AI reads what the user means; code never matches keywords. Who may see what does not change.

Edge cases

  • A default never widens what a contact may see: a dealer's "latest DO" is the latest it may see.
  • The "say so" line is translated (Malay, Chinese) like every other label.
  • A default that finds nothing says what was searched and how to change it; it does not fall back to the question.
  • Rewording the same question still counts as the same question for the loop breaker.
  • When the user actually answers, the count resets.
  • Handover offer respects each contact's handover switch; without it: "Please refer to your salesman."
