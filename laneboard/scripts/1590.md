# Hand test: PR #1590 WC-SEAT-COMPAT (seat cover links: one-off flyer script + product page Compatible section)

Built to the Lavish-approved mockup v3 (`documentation/plans/products/mockups/07-wc-seat-compat.html`).
There is no flyer page: the flyer is linked once by a script, and from then on people keep the
links by hand in the product page's Compatible section (Variants tab, under Alternatives).

## URL
crew test copy

## Setup
Crew runs these on the test copy (backend directory, shared dev DB). The owner runs no commands.

1. Migration: the crew-migration SQL posted on the PR (table `product_compatibility`), or
   `alembic upgrade head` on the copy.
2. Dry run, writes nothing:
   `venv/bin/python scripts/oneoff/link_seat_cover_flyer.py`
   Save the output; the owner reads it in step 1.
3. Apply:
   `venv/bin/python scripts/oneoff/link_seat_cover_flyer.py --apply`
   Then run the same command again; it must say `0 links written`.
4. Do NOT run `--retire-spec` yet: it removes the Seat Cover spec values on the shared dev DB.
   It is step 12, after the owner's checks.
5. Sign in to the CRM as the owner (products edit).

## Steps
1. Read the dry-run output from Setup 2.
2. Read the second `--apply` output from Setup 3.
3. CRM sidebar: Products > All Products. Search `SRTWC8383-RL-MBL`, open it, open the `Variants` tab.
4. Scroll to the `Compatible` section under `Alternatives`.
5. Open `SRTWC8383-RL-UF` the same way, Variants tab.
6. Open `SRTWC8122` the same way, Variants tab.
7. Open any SRTWC8383 SKU that the dry run listed as UNRESOLVED, Variants tab.
8. Open `SRTSCBD824-BL` the same way, Variants tab.
9. On `SRTSCBD407`, Variants tab: click `Add compatible`, keep `WC`, pick an SRTWC8383 SKU ending `-SC`, click `Add`.
10. Still on `SRTSCBD407`: click `Add compatible`, keep `WC`, pick `SRTWC8066-RL` (or any WC not yet listed), click `Add`; then click `Unlink` on that row and wait 5 seconds.
11. Narrow the browser to phone width on the same Variants tab.
12. Crew, after the owner's OK: `venv/bin/python scripts/oneoff/link_seat_cover_flyer.py --apply --retire-spec`, then open Specifications in the sidebar and look for Seat Cover.

## Expected
1. One `LINK  row N  <printed code> -> <seat cover>  SKU <sku>` line per SKU it will link; `UNRESOLVED  <sku>  <reason>` lines (reasons: finish_not_printed, sub_model_not_printed, unknown_segment, ambiguous, not_printed); `MISSING` lines for printed models with no SKU or a cover not in the catalogue; no SKU ending `-SC` anywhere; the last line reads `DRY RUN: N links to write`.
2. `0 links written, N already linked.` (same N as the dry run).
3. The Variants tab shows, in order: Variant of, Variants, Alternatives, then `Compatible (1)`.
4. `Seat covers that fit` lists `SRTSCBD823-MBL` with a blue `Flyer` badge and an `Unlink` button; `Fits these WCs` shows `No WCs`. Never SRTSCBD331-UF or a BL cover.
5. `SRTSCBD331-UF` only, with a `Flyer` badge.
6. `SRTSCBD333-UF` and `SRTSCBD333A-UF`, both with `Flyer` badges.
7. `Compatible` with `No seat covers` and `No WCs`: nothing was invented for it.
8. `Fits these WCs` lists the SRTWC8383 and SRTWC8152 SKUs ending `-BL` that the dry run linked to SRTSCBD824-BL.
9. A red toast: `<code> is a seat cover, not a WC.` Nothing is added.
10. The row appears with an amber `Manual` badge; Unlink shows an `Unlinking in ...s` countdown with `Cancel`, then the row disappears. No confirm dialog.
11. The section fits the phone width with no sideways scroll.
12. The script prints `N Seat Cover spec values removed.`; the Seat Cover specification is no longer active. If it instead prints `Refused: ...`, a company holding a value has no flyer link and nothing was written.
