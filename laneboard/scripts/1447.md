6. Expected numbers come from the copy itself, read-only. This file holds no figures or names (the
   repo is public). Run this for each check in Expected, setting the four values in `p`:
   ```sql
   WITH p(brand, wc_only, d_from, d_to) AS (VALUES ('sorento', true, DATE '2026-01-01', DATE '2026-12-31')),
   l AS (
     SELECT coalesce(sa.sales_agent, '(no agent)') AS agent,
            sol.qty_ordered AS q_ord,
            least(sol.qty_delivered, sol.qty_ordered) AS q_del,
            coalesce(sol.line_total, 0) AS a_ord,
            coalesce(round(coalesce(sol.line_total, 0) * least(sol.qty_delivered, sol.qty_ordered)
                           / nullif(sol.qty_ordered, 0), 2), 0) AS a_del,
            (so.status = 'open' AND sol.line_status = 'open') AS open_line
       FROM p
       JOIN sales_order_lines sol ON true
       JOIN sales_orders so ON so.id = sol.sales_order_id
       JOIN products p2 ON p2.id = sol.product_id
       JOIN brands b ON b.id = p2.brand_id
       LEFT JOIN product_categories pc ON pc.id = p2.category_id
       LEFT JOIN sales_agents sa ON sa.id = so.sales_agent_id
      WHERE so.status <> 'cancelled' AND sol.line_status <> 'cancelled'
        AND coalesce(sol.required_date, so.order_date) BETWEEN p.d_from AND p.d_to
        AND lower(b.brand_name) = p.brand
        AND (NOT p.wc_only OR pc.class_label = 'Water Closet'))
   SELECT agent,
          sum(q_ord) AS ordered_qty, sum(q_del) AS delivered_qty,
          sum(CASE WHEN open_line THEN q_ord - q_del ELSE 0 END) AS outstanding_qty,
          sum(a_ord) AS ordered_rm, sum(a_del) AS delivered_rm,
          sum(CASE WHEN open_line THEN a_ord - a_del ELSE 0 END) AS outstanding_rm
     FROM l GROUP BY agent ORDER BY delivered_qty DESC;
   ```
   Sort by the column the step ranks by. A row whose qty and RM are both 0 on that basis is not
   ranked. The copy is multi-company: add `AND so.company_id IN (<the contact's companies>)` if the
   contact does not see every company.
7. The ranking route allows 10 rankings per contact per 10 minutes. The staff steps run 6. Rerunning
   straight away can show `Too many reports in the last 10 minutes.`: wait 10 minutes.

### Known model variance (accepted by the owner, 4 Oct)

The parser decides every reading (owner rule: the code never reads the message text). The owner kept
`gpt-5.4-mini` and accepted its variance, with no extra rules (option (b), 4 Oct). Measured on the
previous prompt (md5 `414256b0`; the current one adds only main's low stock and trap-specs text), staff steps 1 to
14, two runs: 11 and 10 of 14. Every ranking that ran had the
right figures for the basis in its header. What varies:

- On a bare reply ("this year", "amount", "qty") the parser can copy a basis or metric from an earlier
  message, so a clarify question is skipped and an ORDERED ranking runs. The header says `ordered
  sales`; the figures are right for that basis. Steps 2, 10 and 11 are where this shows.
- "by outstanding" (step 5) was once read as an outstanding order lookup, and "top 5" (step 6) once as
  a top selling ask.
- A missed answer is asked once more; a second miss ends the ask with a line saying so.

Score a step as a PASS when it matches Expected, and note any variance above as variance, not a defect.
For comparison, one run on `gpt-5.4` passed 14 of 14 (not adopted).
