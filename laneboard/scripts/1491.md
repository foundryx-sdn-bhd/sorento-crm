# Hand test #1491 (AI-ALLOWED-GATE)

## URL
crew test copy

## Setup

1. Apply the crew-migration SQL from PR #1491 (adds `respond_contacts.chatbot_allowed`; every contact existing at that moment reads allowed, every contact created afterwards starts blocked).
2. Block egress to respond.io on the test copy before step 5 (the dev DB carries real respond.io credentials; a live turn must send nothing): unset `RESPOND_API_KEY` on the copy's backend, or point `RESPOND_BASE_URL` at an unreachable host.
3. Sign in as a user with `user_management.contacts.edit` (an admin is fine).
4. Pick one synced contact on the dev DB that has chatted before (TESTER, e.g. Mr Loo, respond 900000039; the console borrows the contact's last real WhatsApp envelope, so a contact with no chat history cannot be picked) and note one respond.io id that has chatted but has NO contact row in the CRM (UNKNOWN, e.g. 551719711, the incident contact).
5. The console and Chat History are under System > Messaging in the sidebar.

## Steps

1. From the sidebar open Users & Access > People > Internal Users (the Respond contacts list; also reachable from the apps menu as "Internal Users - Respond contacts"). Read the "AI replies" column for TESTER.
2. Open TESTER, open the Chatbot tab. Read the "AI replies allowed" switch and the line under it.
3. On the Chatbot Console, pick TESTER and send "stock SRTWC8517".
4. On TESTER's Chatbot tab, untick "AI replies allowed". Reload the page and read the switch.
5. On the Chatbot Console, as TESTER, send "stock SRTWC8517" again.
6. As TESTER, send "can I talk to a human".
7. Open System > Messaging > Chat History, find TESTER's latest turn and open it.
8. Back on the contacts list, set the filter "AI replies: AI replies blocked". Read the list.
9. Tick TESTER's switch again. On the Console, as TESTER, send "stock SRTWC8517".
10. On the Console, pick UNKNOWN (the picker takes a bare respond.io id when that id has chatted before; otherwise skip this step and read step 10 in Expected) and send "hi".
11. On the test copy's shell, run `python scripts/set_contact_ai.py --status` from `sorento_crm_backend/`.
12. On the contacts list, click Add and create a contact with a new phone number (e.g. +60100000999, name "ZZT New"). Open it, open the Chatbot tab.

## Expected

1. Step 1: TESTER's "AI replies" cell reads "Allowed". Every existing contact reads Allowed.
2. Step 2: the switch "AI replies allowed" is on (checked), with "When off, the chatbot sends this contact nothing, not even an error." under it. It is the first switch in the grid.
3. Step 3: the bot answers the stock question as before (a stock answer or a did-you-mean list), with a branch chip such as `business_query`.
4. Step 4: after the reload the switch stays off. The toast said "Chatbot settings saved".
5. Step 5: the console shows ONE bot bubble reading "(no reply)" with the chip `ai_not_allowed`. No stock answer, no "Sorry, I ran into a problem".
6. Step 6: the same "(no reply)" bubble with chip `ai_not_allowed`. No escalation offer, no routing picker, no PIC assigned, no SLA row.
7. Step 7: the turn's headline reads "Not allowed", status done, lane "AI not allowed"; the timeline has one stage, Received, marked skipped, with the line "AI not allowed for this contact; sent no reply". Nothing after it. No outbound respond.io request appears in Integration Logs for that turn.
8. Step 8: the list shows TESTER (and any other blocked contact) only; TESTER's "AI replies" cell reads "Blocked".
9. Step 9: the switch is on again and the bot answers the stock question as in step 3.
10. Step 10: "(no reply)" with chip `ai_not_allowed`, the same as a blocked contact. If the picker cannot take an unknown id, this case is covered by `tests/chatbot/test_ai_allowed_gate.py::TestUnknownContact` (no row, zero actions, turn recorded done).
11. Step 11: the banner prints `AI REPLIES STATUS` with allowed / blocked / total counts; blocked = 0 if TESTER was ticked back on in step 9.
12. Step 12: the new contact's "AI replies allowed" switch is OFF (a contact added after the migration starts blocked); its list cell reads "Blocked". Delete the test contact afterwards if you like (hard delete, countdown button).
