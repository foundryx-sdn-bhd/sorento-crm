## Setup

1. No migration, no seed: the lane changes one arm of the chatbot engine (`turn/decide.py`). The
   MCP server on the test copy needs no restart (presenters are untouched).
2. Chatbot Console contact DEALER: a contact that holds the `Sales order outstanding` reveal
   (`sales_orders.outstanding`). Contact 900000008 holds it on the dev copy since the 13 Sep
   outstanding-report lane; any contact with that grant works.
3. Product `<CODE>`: one with delivery order rows still outstanding for DEALER's companies. The
   13 Sep case used `SRTWT7445` (DO rows across 2026 on the prod copy). Read-only SQL on the dev
   copy to find one if it has moved on:

   ```sql
   SELECT p.product_code, COUNT(DISTINCT o.id) AS open_dos
   FROM orders o
   JOIN order_lines l ON l.order_id = o.id
   JOIN products p ON p.id = l.product_id
   LEFT JOIN order_statuses s ON s.id = o.order_status_id
   WHERE o.deleted_at IS NULL
     AND (o.order_status_id IS NULL OR lower(s.status_code) NOT IN ('delivered', 'completed')
          OR o.actual_delivery_date IS NULL)
   GROUP BY p.product_code
   HAVING COUNT(DISTINCT o.id) BETWEEN 2 AND 15
   ORDER BY open_dos DESC
   LIMIT 10;
   ```

4. The console is a dry run. Nothing reaches WhatsApp. The quick reply chips under a reply are
   the same chips respond.io shows; the console sends a tapped chip as its label TEXT, exactly as
   respond.io does in production.
