# Hand test: PR #1623 AC-CANCEL-CRM (AutoCount Cancel SO derives cancelled qty)

## URL

crew test copy

## Setup

Crew runs every command; the owner runs none. `$URL` is the test copy, `$KEY` its backend
`EXTERNAL_API_KEY`, `$DATABASE_URL` its database (read only below).

1. Apply both `crew-migration` blocks from the PR (tables, `qty_cancelled`,
   `cancelled_by_cancel_doc`, the `scm.cancel_*` / `scm.consignment*` slugs).
2. SO373923's three lines read delivered 0 / open on the dev DB today; the test needs them as
   AutoCount sends them (TransferedQty 36, so `closed`). Re-push the SO through the ingest
   endpoint, never by editing rows:
   - `REF=$(psql "$DATABASE_URL" -Atc "SELECT r.source_ref FROM integration_references r JOIN sales_orders s ON s.id::text = r.entity_id WHERE r.entity_type = 'sales_orders' AND s.so_number = 'SO373923'")`
   - `curl -s -X POST "$URL/api/v1/external/read/sales_orders" -H "X-API-Key: $KEY" -H "Content-Type: application/json" -d "{\"companyCode\":\"SRT\",\"source_refs\":[\"$REF\"]}" > so373923.json`
   - `jq '{companyCode:"SRT", records:[.records[0] | .lines |= map(if (.product_code|IN("CB110","CB110-R","CB110LP")) then .qty_delivered = 36 else . end)]}' so373923.json > so373923-push.json`
   - `curl -s -X POST "$URL/api/v1/external/ingest/sales_orders" -H "X-API-Key: $KEY" -H "Content-Type: application/json" -d @so373923-push.json`
   - Check: `psql "$DATABASE_URL" -c "SELECT p.product_code, l.qty_ordered, l.qty_delivered, l.line_status FROM sales_order_lines l JOIN sales_orders s ON s.id = l.sales_order_id JOIN products p ON p.id = l.product_id WHERE s.so_number = 'SO373923' AND p.product_code IN ('CB110','CB110-R','CB110LP')"` reads 36 / 36 / closed for all three.
3. The fake Cancel SO below is `ZZXS-HAND-1`, DocKey 990001: it names the SO and the item but no
   line key, so the item match is what runs.

## Steps

1. Sign in. From the sidebar open the fulfilment planning board and find SO373923. Note CB110,
   CB110-R and CB110LP listed with Planned 36 each, and that Confirm refuses them ("components
   add up to 0 and the line is open for 36").
2. Crew runs: `curl -s -X POST "$URL/api/v1/external/ingest/cancel_sales_orders" -H "X-API-Key: $KEY" -H "Content-Type: application/json" -d '{"companyCode":"SRT","book":"db1","records":[{"DocKey":990001,"DocNo":"ZZXS-HAND-1","DocDate":"2026-10-13","Cancelled":"F","LastModified":"2026-10-13T10:00:00","Details":[{"DtlKey":991001,"Seq":1,"ItemCode":"CB110","Qty":36,"FromDocType":"SO","FromDocNo":"SO373923","FromDocDtlKey":0},{"DtlKey":991002,"Seq":2,"ItemCode":"CB110-R","Qty":36,"FromDocType":"SO","FromDocNo":"SO373923","FromDocDtlKey":0},{"DtlKey":991003,"Seq":3,"ItemCode":"CB110LP","Qty":36,"FromDocType":"SO","FromDocNo":"SO373923","FromDocDtlKey":0}]}]}'`
3. Reload the board and find SO373923 again.
4. Confirm the order's remaining lines on the board as usual.
5. From the sidebar open Sales Orders, open SO373923, then the Lines tab.
6. Crew runs the same `curl` as step 2, unchanged.
7. Crew runs: `curl -s -X POST "$URL/api/v1/external/ingest/cancel_sales_orders/deletions" -H "X-API-Key: $KEY" -H "Content-Type: application/json" -d '{"companyCode":"SRT","book":"db1","doc_date_from":"2026-10-13","doc_date_to":"2026-10-13","doc_keys":[990001]}'`
8. Reload the SO373923 Lines tab, then the board.

## Expected

- Step 2: response `"created":1`, `"failed":0`; record `db1:XS:990001` reads `"outcome":"created"`
  with no `cancel_line_waiting` / `cancel_line_unmatched` warning.
- Step 3: CB110, CB110-R and CB110LP are no longer listed as lines to plan (the same as a line
  AutoCount itself cancels). Any order inquiry rows on them are cancelled with the note
  "Transferred to Cancel SO: ZZXS-HAND-1".
- Step 4: Confirm goes through; no refusal names the three lines.
- Step 5: the three lines show Ordered 36, Delivered 0, Outstanding 0, status Cancelled.
- Step 6: the record reads `"outcome":"unchanged"`; nothing on the board or the SO changes.
- Step 7: the response record reads `"outcome":"deactivated"`.
- Step 8: the three lines show Delivered 36 and status Completed (closed), as after Setup 2;
  they are back on the board with Planned 36. The order inquiry rows retired at step 3 stay
  cancelled.
