# Hand test: PR #1622 OI-REJECT-NOTIFY (email + in-app to the OI raiser when rows are rejected, one per OI)

## URL

crew test copy

## Setup

Crew setup on the test copy of this PR's head (the sha in the latest crew-done comment). The owner
runs no commands.

1. Apply the crew-migration SQL from the PR (one template `order_inquiry_rejected_default` and one
   automation `Order inquiry rejected`, both guarded by WHERE NOT EXISTS). Check: System
   Management, Automations lists "Order inquiry rejected", enabled.
2. SMTP: the dev DB's `system_settings` carries `smtp_host=asdfmail.sorento.com.myxx:465`, which
   does not resolve, and the copy's worker drains the `notifications` queue. So every mail this
   test creates is attempted and ends with status `failed` in Outgoing Mails (never `queued`,
   never delivered). The row, its recipient and its rendered preview are what this test reads;
   the `failed` status is expected and is not a defect of this PR.
3. Crew notes the newest row id in System, Outgoing Mails before step 1, so new rows are easy to
   tell apart.
4. Pick two open Order Inquiries raised by an ACTIVE user who is NOT the owner (for example
   Eling): OI-A with at least 3 rows in state Raised, Partly linked or Placed that are not yet
   rejected, OI-B with at least 1 such row. Note both OI numbers, their SO numbers and customers.
   Also pick one OI the owner raised themselves (OI-C) with one such row; skip steps 10 and 11
   if none exists.
5. The owner signs in as themselves (holds Order Inquiries acknowledge). Crew provides a way to
   sign in as the raiser for steps 8 and 9.

## Steps

1. Open the URL, sign in, open Project Sales, then Order Inquiries.
2. Search OI-A's SO number and tick 2 of OI-A's rows.
3. Press Reject, enter the reason `Supplier discontinued this finish`, confirm.
4. In the sidebar open System, then Outgoing Mails, and search `OI rejected`.
5. Open the newest row and read its preview.
6. Back in Order Inquiries, tick 1 more row of OI-A and 1 row of OI-B in the same selection,
   press Reject with the reason `No stock at supplier`.
7. Refresh Outgoing Mails and search `OI rejected` again.
8. Sign in as the raiser and open the notification bell.
9. Click the notice `<OI-A no>: 2 lines rejected by purchasing`.
10. Sign back in as the owner; in Order Inquiries tick OI-C's row, Reject with the reason
    `test self`.
11. Refresh Outgoing Mails and search `OI rejected`.

## Expected

1. After step 3: exactly ONE new `OI rejected` row, subject `OI rejected: <OI-A no> <OI-A SO no>`,
   recipient the raiser only, status `failed` (setup 2).
2. Step 5 preview: red heading `Rejected: <OI-A no>`; a table OI NO / S/O NO / CUSTOMER / PROJECT
   with OI-A's values; a table ITEM CODE / QTY / DELIVERY DATE with exactly the 2 rejected lines,
   dates dd/mm/yyyy; `Reason: Supplier discontinued this finish`; `Rejected by <owner name>
   (<owner email>) on <today dd/mm/yyyy HH:MM, Malaysia time>.`; an `Open in Order Inquiries`
   link ending `/project-sales/order-inquiries/<OI-A id>`. No ` · ` and no `None` anywhere.
3. Step 7: exactly TWO new `OI rejected` rows: one for OI-A listing 1 line, one for OI-B listing
   1 line, both with `Reason: No stock at supplier`.
4. No reject in this test creates a handover row (no new row whose subject starts `OI: `).
5. Step 8: three new bell notices: `<OI-A no>: 2 lines rejected by purchasing` (body
   `<OI-A SO no> <OI-A customer>. Reason: Supplier discontinued this finish`), then
   `<OI-A no>: 1 line rejected by purchasing` and `<OI-B no>: 1 line rejected by purchasing`.
6. Step 9: opens the OI-A detail page.
7. Step 11: NO new `OI rejected` row at all for OI-C (the raiser is the rejecter and the seeded
   automation has no other recipient), and the owner gets no bell notice for it.
