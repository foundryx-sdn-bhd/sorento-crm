# Hand test #1500 (QUICK-REPLY-NAMES)

## URL
crew test copy

## Setup

1. Sign in as an admin and open System Management > Chatbot Console from the sidebar.
2. Pick a test contact whose company scope includes Sorento and who has the order enquiries grant (the contact used for earlier chatbot hand tests is fine).
3. Have three customers on the dev DB whose names share a prefix longer than 20 characters, e.g. "SAMPLE ONG BROTHERS", "ONG BROTHERS TILING TRADING SDN BHD" and "ONG BROTHERS TILING TRADING SDN BHD (SAMPLE)". If they are missing, add them under Master Data > Customers (Sorento company) before starting.
4. Have one product code that is close to, but not equal to, a real code (for the did-you-mean step), e.g. a real code with the last character changed.

## Steps

1. In the console, send: `DO for ong brothers`
2. Look at the reply and at the quick replies row under it.
3. Send: `2`
4. Send: `do you have stock for <the near-miss code from Setup 4>`
5. Look at the quick replies row under that reply.
6. Send a message that opens an escalation offer, e.g. `escalate this to the customer service team`
7. Look at the quick replies row under that reply.
8. Open System Management > Chat History, find the turn from step 1 and open it.

## Expected

1. The reply is the customer picker: "Which customer do you mean? Please choose:" followed by the three numbered lines, one per customer, each ending with the company code in brackets.
2. The quick replies row is EMPTY for that turn. No customer name appears as a button.
3. The bot answers for the second customer in the list (the delivery order list or "no orders matched" for that customer). It does not re-ask "Which customer do you mean?".
4. The reply says it could not find the code and either names the closest matches in a sentence ("Did you mean ...") or lists them as a numbered list.
5. NO buttons under the did-you-mean, whether it names the codes in a sentence or lists them numbered: product codes are free text. Typing a listed number or a listed code still picks it.
6. The reply asks whether to escalate (yes/no wording) or which team.
7. The buttons are the yes/no pair, or the team names; at most three buttons; none longer than 20 characters. If a team name is longer than 20 characters the row is empty and the text still names the teams.
8. The stored turn shows the same reply text as the console did, with quick replies empty for the picker turn (what Chat History shows matches what the customer would have been sent).
